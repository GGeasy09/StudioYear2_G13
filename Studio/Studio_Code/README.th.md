# เฟิร์มแวร์ Base System — หุ่นยนต์หมุน 1 องศาอิสระ (STM32G474)

เฟิร์มแวร์สำหรับ **หุ่นยนต์หมุนแบบ 1 องศาอิสระ (1-DOF)** ตัวไมโครคอนโทรลเลอร์รันตัวควบคุมแบบ
คาสเคด (ตำแหน่ง/ความเร็ว) ร่วมกับ feedforward และตัวประมาณสถานะแบบ Kalman ขับมอเตอร์ผ่าน
ลูปควบคุมแบบเรียลไทม์ และเชื่อมต่อกับโปรแกรมบน PC ผ่าน **Modbus RTU** ควบคุมได้ 2 ทาง:

- **ควบคุมที่เครื่อง (Local)** ผ่าน **จอยสติ๊ก / ปุ่ม / สวิตช์โหมด** บนตู้ไฟ (`Trust_Joystick`)
- **ควบคุมระยะไกล (Remote)** ผ่านโปรแกรม **Base System** บน PC — web UI → WebSocket → Modbus
  ผ่านสาย USB serial (`Trust_Basesystem`) ดูฝั่ง PC และตารางรีจิสเตอร์ทั้งหมดที่ `../Base_system/README.md`

การทำงานที่รองรับ: **Homing**, **Jog**, **Point-to-point**, **ลำดับ Auto pick-&-place**,
และ **การทดสอบ Performance / Precision** พร้อมระบบความปลอดภัย **Emergency** และ **Soft-stop**

---

## 1. ฮาร์ดแวร์เป้าหมาย

| รายการ | รายละเอียด |
|------|--------|
| MCU | STM32G474 (Cortex-M4F, FPU แบบ single-precision, CMSIS-DSP) |
| ขับมอเตอร์ | **TIM1 CH1** PWM (ฟังก์ชัน `PWM()` ใน `system_state.c`) |
| ฐานเวลาไมโครวินาที | **TIM2** (นับอิสระ ใช้กับการจับเวลา trajectory) |
| เอ็นโคเดอร์ | **TIM3** โหมด encoder (อ่านตำแหน่งแบบ quadrature) |
| ลูปควบคุม (ISR) | คอลแบ็ก **TIM20** ที่ **2 kHz** (`Robot_Period_Control_Loop`) |
| จับเวลา Modbus | **TIM16** (ช่องว่าง T1.5 / T3.5) |
| การสื่อสาร | **USART2**, **230400 baud, 8 data, Even parity, 1 stop**, slave addr **21 (0x15)** |
| CAN | **FDCAN** (ตั้งค่าไว้) |
| Homing | สเตตแมชชีนของเซนเซอร์ proximity อ้างอิงตำแหน่ง |
| I/O แบบดิจิทัล | ปุ่มจอยสติ๊ก, สวิตช์โหมด, ไฟ pilot, รีเลย์ power/auto, รีเลย์กริปเปอร์ และเซนเซอร์รีด |

ข้อตกลงเชิงกล: **1 รู (hole) = 5°** (`DEG_PER_HOLE`) ค่าบวก = ทวนเข็ม (CCW), ค่าลบ = ตามเข็ม (CW)

## 2. การคอมไพล์และแฟลช

1. เปิด **STM32CubeIDE** แล้ว import โปรเจกต์นี้ (มีไฟล์ `.cproject` / `.project`)
2. การตั้งค่าฮาร์ดแวร์อยู่ใน **`Base_System.ioc`** — เปิดด้วย CubeMX เพื่อแก้ขา/เพอริเฟอรัล แล้ว generate ใหม่
3. เลือกคอนฟิก **Debug** แล้ว build (`make -j all`)
4. แฟลช / ดีบักผ่าน **ST-Link** (`Base_System Debug.launch`)
5. หากควบคุมผ่าน PC ให้รันโปรแกรม Base System แล้วเลือกพอร์ต ST-Link Virtual COM

## 3. โครงสร้างโปรเจกต์

(`dma.c`, `fdcan.c`, `gpio.c`, `tim.c`, `usart.c`, `stm32g4xx_*`, `sys*.c`) เป็นไฟล์มาตรฐาน

| ไฟล์ | หน้าที่ |
|------|------|
| `Core/Src/main.c` | จุดเริ่มต้น, การ init, ลูปหลัก, **สเตตแมชชีนหลัก** (`Robot_State_Process`) และ **ลูปควบคุม 2 kHz** (`Robot_Period_Control_Loop`) เก็บอ็อบเจกต์ส่วนกลาง (`sys_state`, `Controller`, `Kalman`, `traj_mgr`, สถานะจอย/กริปเปอร์/sequence/test) |
| `Core/Src/system_state.c` · `Inc/system_state.h` | อ่าน/คำนวณเอ็นโคเดอร์, ส่งออกมอเตอร์ **`PWM()`**, **`SYSTEM_STATE_Homing()`**, จัดการตำแหน่ง, ฟังก์ชันแปลง deg↔rad นิยาม `SYSTEM_STATE`, `Encoder`, `Proximity` |
| `Core/Src/elec_cabient.c` · `Inc/elec_cabient.h` | I/O ของตู้ไฟ: **`SYSTEM_STATE_Joystick_Update()`** (สวิตช์โหมด + ปุ่ม + soft-stop), รีเลย์ไฟ pilot/ramp (`PilotRamp_SetPower`, `PilotRamp_SetAuto`, `PilotLamp_SetWhite`), การควบคุมกริปเปอร์ (รีเลย์ + เซนเซอร์รีดจำกัดระยะ) |
| `Core/Src/trajectory.c` · `Inc/trajectory.h` | ตัววางแผนการเคลื่อนที่ — **Trapezoidal**, **S-curve (7 ช่วง)**, **Min-jerk**, **Min-jerk แบบจำกัดความเร็ว** — และ API ระดับสูง **`TrajManager`** (`_Init`, `_Plan`, `_Step`, `_DynTime`) |
| `Core/Src/cascade.c` · `Inc/cascade.h` | **ตัวควบคุมคาสเคด**: PID ตำแหน่งวงนอก → PID ความเร็ววงใน พร้อม **feedforward** ของมอเตอร์และเทอม disturbance |
| `Core/Src/kalman.c` · `Inc/kalman.h` | **ตัวประมาณ Kalman 4 สถานะ** (ตำแหน่ง, ความเร็ว, disturbance, ความเร่ง) ใช้เมทริกซ์ CMSIS-DSP |
| `Core/Src/BaseSystem.c` · `Inc/BaseSystem.h` | **Modbus RTU slave**: รับ/แยก/ตรวจ CRC เฟรม, ตารางรีจิสเตอร์ 50 ตัว, ถอดรหัสคำสั่ง (`BaseCmd`), heartbeat (enum `CMD_MODE_*`, `CMD_TEST_*`, `CMD_GRIPPER_*`) |
| `Core/Inc/motor_params.h` | ค่าคงที่โมเดลมอเตอร์: ค่าคงที่แรงบิด/back-EMF, ความเฉื่อย, การหน่วง, ความต้านทาน, ความเหนี่ยวนำ, ค่าคงที่เวลาฟิลเตอร์ FF |

## 4. สถาปัตยกรรมการควบคุม

ทำงานทุก 0.5 มิลลิวินาที ภายใน `Robot_Period_Control_Loop` (TIM20 @ 2 kHz):

```
 เอ็นโคเดอร์ (TIM3) ──► ตัวประมาณ Kalman ──► สถานะ: ตำแหน่ง / ความเร็ว / disturbance
                                              │
 TrajManager_Step ──► ค่าอ้างอิง (pos, velo) ─┤
                                              ▼
                          คาสเคด: PID วงนอก (ตำแหน่ง) ──► PID วงใน (ความเร็ว)
                                              + feedforward (โมเดลมอเตอร์)
                                              ▼
                                   แรงดัน ──► PWM() ──► ขับมอเตอร์ TIM1
```

เมื่อไม่มี trajectory ทำงาน (`traj_mgr.running == 0`) ตัวควบคุมจะค้างที่ตำแหน่งคำสั่งล่าสุด
(`sys_state.cur_pos`) และมีการชดเชยแรงเสียดทานสถิตเล็กน้อยที่ขั้น PWM

ค่าเกนเริ่มต้น (ส่วนบนของ `main.c`):

| ลูป | Kp | Ki | Kd |
|------|----|----|----|
| วงใน (ความเร็ว) | 0.52259 | 10.2259 | 0.0 |
| วงนอก (ตำแหน่ง) | 2.0 | 0.0 | 1.0 |

## 5. โหมดการทำงานและสเตตแมชชีน

`Robot_State_Process()` ทำงานในลูปหลัก (ไม่ใช่เรียลไทม์) สิทธิ์การควบคุมเลือกด้วย `sys_state.trust`:
**`Trust_Joystick`** (ตู้ควบคุมที่เครื่อง) หรือ **`Trust_Basesystem`** (PC/Modbus)

โหมดของ Base System ใช้ค่าแบบ one-hot ที่รีจิสเตอร์ `0x01`:

| โหมด | ค่า | พฤติกรรม |
|------|------:|----------|
| Idle | 0 | ไม่มีคำสั่ง |
| **Home** | 1 | ทำ homing ด้วย proximity แล้วเคลื่อนไปตำแหน่งอ้างอิง home |
| **Jog** | 2 | ขยับทีละสเต็ป (องศา) จากตำแหน่งปัจจุบันต่อหนึ่งคำสั่ง |
| **Auto** | 4 | Point-to-point หรือ **ลำดับ** pick-&-place (`seq`: ไปหยิบ → จับ → ไปวาง → ปล่อย ต่อหนึ่งคู่) |
| **Set home** | 8 | บันทึกตำแหน่งปัจจุบันเป็นจุดอ้างอิงของ Base System (ทำได้เฉพาะจอยสติ๊ก) |
| **Test** | 16 | **Performance** (S-curve ไป/กลับ) หรือ **Precision** (วิ่ง min-jerk ไป-กลับ init↔final ซ้ำ) |

ระบบความปลอดภัย (ตรวจก่อนทุกรอบ):

- **Emergency** (PA4): หยุด ISR, ตัด PWM, ล้างทุกกิจกรรม, ล็อกค้างจนกว่าจะปล่อย เมื่อปล่อยจะอ่านตำแหน่งใหม่จากเอ็นโคเดอร์แล้วเริ่ม homing ใหม่
- **Soft stop** (จอยสติ๊ก หรือ `0x25`): จบ/ยกเลิกการเคลื่อนที่ แล้วกลับสู่สถานะ *รอคำสั่ง*

## 6. จอยสติ๊ก / การควบคุมที่เครื่อง (`Trust_Joystick`)

ตู้ไฟมี **สวิตช์โหมด**, ปุ่มสี 6 ปุ่ม, ปุ่มขาวสำหรับเดินทีละสเต็ป 2 ปุ่ม และสาย soft-stop
อินพุตถูกอ่านโดย `SYSTEM_STATE_Joystick_Update()` ทุกการกระทำเป็นแบบ **ตรวจขอบขาขึ้น/ลง**
(ทำงานครั้งเดียวตอนกด คือสัญญาณ raw เปลี่ยนจาก `1 → 0`)

**ผังตำแหน่งจริง** (ด้านหน้าแผงตู้ ตามที่เดินสาย):

```
   ( ขาว-1 )                         [ ⌷ ] สวิตช์โหมด
   ( ขาว-2 )
                                     ╔═══════╗
                                     ║  DB9  ║  serial (Modbus/USART2)
   ( ดำ )                            ╚═══════╝

 ( น้ำเงิน )  ( เหลือง )             [□□] เทอร์มินอลบล็อก
   ( แดง )
       │
   สาย soft-stop / e-stop
```

ปุ่มขาวทั้งสอง **วางเรียงแนวตั้ง** บนแผง แต่ในเฟิร์มแวร์ตั้งชื่อว่า **White-left (PC1)** (ปุ่มบน)
และ **White-right (PB1)** (ปุ่มล่าง) หมายเหตุ: มีการลิงก์ทางฮาร์ดแวร์ การกดปุ่มขาว "ขวา" อาจ
กระตุ้นสาย "ซ้าย" ด้วย (ดูคอมเมนต์ใน `elec_cabient.h`)

**ตารางขาฮาร์ดแวร์ของปุ่ม** (`elec_cabient.h`):

| ปุ่ม | ขา | ปุ่ม | ขา |
|--------|-----|--------|-----|
| สวิตช์โหมด | PA15 | ขาว-ซ้าย (บน) | PC1 |
| ดำ | PA9 | ขาว-ขวา (ล่าง) | PB1 |
| แดง | PA8 | น้ำเงิน | PB2 |
| เหลือง | PB9 | Soft-stop | PB7 |

### 6.1 ปุ่มขาว (เดินทีละรู) — ใช้ได้ทั้งสองโหมด
- **ขาว-ซ้าย** → ทิศ **+** (CCW); **ขาว-ขวา** → ทิศ **−** (CW)
- ขนาดสเต็ปขึ้นกับสวิตช์โหมด: **โหมด 0 = 5 รู** ต่อการกด (`5 × DEG_PER_HOLE`),
  **โหมดอื่น = 1 รู** ต่อการกด แต่ละครั้งจะสั่งเคลื่อนแบบ min-jerk

### 6.2 โหมด 0 — ควบคุมกริปเปอร์โดยตรง
| ปุ่ม | การกระทำ |
|--------|--------|
| ดำ | กริปเปอร์ **เปิด (Open)** |
| น้ำเงิน | กริปเปอร์ **ปิด (Close)** |
| เหลือง | กริปเปอร์ **ขึ้น (Up)** |
| แดง | กริปเปอร์ **ลง (Down)** |

### 6.3 โหมด 1 — home / pick / place
| ปุ่ม | การกระทำ |
|--------|--------|
| ดำ | **ตั้ง home** = ตำแหน่งปัจจุบัน |
| น้ำเงิน | **ไปที่ตำแหน่ง home** |
| แดง | เริ่มลำดับ **หยิบ (Pick)** ของกริปเปอร์ |
| เหลือง | เริ่มลำดับ **วาง (Place)** ของกริปเปอร์ |

จากนั้นสเตตแมชชีนของกริปเปอร์จะทำงานทุก tick จนกว่าจะเสร็จ (หรือหมดเวลา)

## 7. พารามิเตอร์ที่ปรับได้ที่สำคัญ

| พารามิเตอร์ | ตำแหน่ง | ค่าเริ่มต้น | ความหมาย |
|-----------|----------|---------|---------|
| คาบลูปควบคุม | `TrajManager_Step` | `0.0005f` | คาบลูป 2 kHz (ต้องตรงกับ TIM20) |
| `DEG_PER_HOLE` | `main.c` | `5.0f` | องศาต่อหนึ่งรู/index |
| `GRIPPER_TIMEOUT_MS` | `main.c` | `5000` | เวลารอสูงสุดต่อการหยิบ/วาง |
| ความเร็วเคลื่อนที่ไดนามิก | `trajectory.c` | `110 °/s` | ความเร็วเดินทางที่ใช้ใน `TrajManager_DynTime` |
| ช่วงเวลาเคลื่อนที่ (clamp) | `trajectory.c` | `0.9 … 3.5 s` | เวลา min-jerk ต่ำสุด/สูงสุดที่คำนวณอัตโนมัติ |
| ค่าทนตำแหน่งถึงเป้า | `main.c` (เฟส seq) | `0.001745f` rad (≈0.1°) | ค่าทนสำหรับเลื่อนสเต็ปลำดับ |
| ค่าเกน PID | `main.c` | ดูหัวข้อ 4 | การจูนคาสเคดวงใน/วงนอก |

> **หมายเหตุ:** ค่าทน 0.1° ค่อนข้างแคบ ถ้าตัวควบคุมนิ่งโดยมี steady-state error ใหญ่กว่านี้
> ลำดับอาจค้างได้ ให้ผ่อนค่า (เช่น `0.00873f` ≈ 0.5°) หากจำเป็น

## 8. อินเทอร์เฟซ Modbus (ฝั่งเฟิร์มแวร์)

หุ่นยนต์เป็น Modbus RTU **slave** (addr 21) ฝั่ง PC จะเขียนคำสั่งไปยัง holding register และอ่าน
สถานะ/ฟีดแบ็กแบบบล็อก:

- **เขียน (PC→หุ่นยนต์):** `0x01` โหมด, `0x05` jog (องศา), `0x06–0x11` พารามิเตอร์ test,
  `0x12–0x22` ลำดับ pick-place, `0x23–0x24` point-to-point, `0x25` soft stop, กริปเปอร์ `0x02–0x04`
- **อ่าน (หุ่นยนต์→PC):** `0x00` heartbeat, `0x26` เซนเซอร์รีด, `0x27` งานปัจจุบัน,
  `0x28/0x29/0x30` ตำแหน่ง/ความเร็ว/ความเร่ง (สเกล **×10**), `0x31` emergency

ตารางรีจิสเตอร์เต็ม ความหมายของบิต การสเกล และกฎ two's-complement: **`../Base_system/README.md`**
การถอดรหัสฝั่งเฟิร์มแวร์อยู่ใน `BaseSystem.c` (struct `BaseCmd`, enum `CMD_*` ใน `BaseSystem.h`)

## 9. หมายเหตุ / การเปลี่ยนแปลงล่าสุด

- `TrajManager` และ API `Init/Plan/Step/DynTime` นิยามใน `trajectory.{c,h}` และถูกใช้ทั่ว `main.c`
- ฟังก์ชัน `*_Compute` ของตัววางแผนทุกตัวกำหนดค่า `out.Complete` ในทุกเส้นทางแล้ว (ก่อนหน้านี้
  การลืมกำหนดค่าเริ่มต้นทำให้ trajectory จบหลังสเต็ปเดียว)
- ทิศของปุ่มขาวและสเต็ป 5 รูในโหมด 0 เป็นไปตามหัวข้อ 6
